# Grok Bot 的续跑 routine（中文）

计划批准、第一批顺利跑完以后再建。把 `<你的账号>` 换成你的 X 账号，`P00X` 换成实际的计划编号，时间换成你习惯的时段，然后把下面整段发给 Bot。

---

请新建一个 routine，名字叫「XFA 取关续跑 P00X」，时间是每天 08:00、10:00、12:00、14:00、16:00、18:00、20:00、22:00。每次运行都用「X 关注分级清理」这个 skill，只处理 `<你的账号>` 的计划 P00X，按下面的步骤做：

1. 运行 `xfa status <你的账号> P00X --json`。
2. 如果 `complete` 为 true，或 `waiting_on_user` 为 true，或计划已过期、已撤销：
   - 运行 `xfa verify <你的账号> P00X`，再运行一次 `xfa status <你的账号> P00X --json`；
   - 仍是这几种情况，才把最终结果发给我，并停用这个 routine；核对后又有可以继续的账号，就接着往下做。
3. 如果 `caps.unsynced` 里有批次：在 x.com 标签页执行 `xfaResult()`，看返回里的 `status`。
   - 还是 `running`：这次什么都不做，等下一次。
   - 是 `done` 或 `stopped: ...`：把返回的文字存成对应的 `batches/BNNN.result.json`，运行 `xfa sync <你的账号> --file <文件>`。
   - 页面没了：在 x.com 新开一个标签页，重新执行同一个 `batches/BNNN.js`。它不会重跑这一批，只会在拿到执行锁后安全收尾、交出结果；然后执行 `xfaResult()`，按上面的办法同步。
   - 返回 refused，说明原来的页面还在跑，等下一次。
   - 实在拿不到，并且已经过期 5 分钟：运行 `xfa batch <你的账号> P00X --abandon BNNN`，再运行 `xfa verify <你的账号> P00X`。
4. 如果 `caps.next_eligible` 还没到，这次不发新批。
5. 可以发时：
   - 先在 x.com 页面跑一次 `xfa probe <你的账号>` 的只读探针，三处账号核对都对才继续；
   - 再运行 `xfa batch <你的账号> P00X`，在同一页面执行生成的 `BNNN.js`；
   - 几秒后读 `window.__xfaStartMessage`，确认已开始。
6. 遇到下面这些情况，就不要发新批：
   - 要登录、要验证；
   - 账号不对；
   - 出现限制提示，或确认弹窗对不上目标；
   - Grok 用量用完；
   - `sync` 报了 ⚠️。

   把原因告诉我，并停用这个 routine，等我处理完再说。

只回一两句进度：今天取关几个、还剩几个、下一批几点。不要逐条复述账号资料，不要重新拉全量数据，不要重新审核，不要扩大名单。

---

说明：

- 每次运行都算 Grok 每周用量，哪怕什么也没做。一天 8 次已经足够，别改成每小时。
- 节奏由脚本控制：每小时最多 18 个，24 小时最多 100 个，每天计划 90 个。
- 页面计时器在两次任务之间如果会停（首次验收会测出来），就让每批在一次任务里跑完，最长 55 分钟。
